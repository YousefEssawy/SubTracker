# Implementation Plan: Strong-Typed Domain Models

**Branch**: `001-strong-type-models` | **Date**: 2026-02-25 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-strong-type-models/spec.md`

---

## Summary

Migrate the SubTracker codebase from untyped JavaScript to a partially-TypeScript project. A new `src/models/` layer defines all domain interfaces and union types. `src/utils/`, `src/services/`, and `src/contexts/` are converted to `.ts`/`.tsx` with `strict: true`. Page and component `.jsx` files remain unchanged but gain typed IntelliSense through their imports.

**Approach**: Bottom-up migration — models → utils → services → contexts. Each layer is fully typed before the next begins, ensuring the build stays green throughout.

---

## Technical Context

**Language/Version**: JavaScript (ES2020) → TypeScript 5.x (partial migration); React 19 with JSX  
**Primary Dependencies**: Vite 7, Firebase 12, React Router 7, Framer Motion 12, Recharts, i18next  
**Storage**: Firebase Firestore (cloud) — no local storage layer  
**Testing**: No test framework currently configured — type-checking via `tsc --noEmit` serves as the primary validation gate  
**Target Platform**: Web (SPA deployed to GitHub Pages)  
**Performance Goals**: Zero impact on runtime performance — TypeScript is compile-time only; Vite strips all types at build time  
**Constraints**: `allowJs: true` + `checkJs: false` required to keep `.jsx` pages working; `noEmit: true` for type-check-only mode  
**Scale/Scope**: ~60 source files; 9 service files, 8 context files, 6 util files targeted for migration; ~17 page files and all component files remain `.jsx`
